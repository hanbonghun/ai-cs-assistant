# 0011. 근거 없는 자동 답변은 코드가 막는다

- 상태: 채택
- 결정 시점: 2026-11-12

## 맥락

실측 평가([ADR 0010](0010-two-eval-sets.md)) 기준선에서, 범위 밖 질문 10건은 검색이 10/10 정확히 비었는데도
(에이전트가 모은 청크 0건) 그중 3~4건을 일반 지식으로 답했다. 저녁 메뉴를 추천했고, 앱 설정 위치와 워치 밴드
호환 여부를 단정했다. 프롬프트에는 이미 "모르면 상담사에게" 라는 취지의 규칙이 있었다.
근거가 없다는 사실은 코드가 이미 알고 있다 — 모은 청크 목록과 주문 조회 결과가 루프 안에 있다.

## 결정

`InquiryAgentService.buildFinalAnswer` 에 경계를 둔다. 모델이 **자동 답변**(needsHumanReview·needsEscalation 모두
false)을 내려 할 때, 이번 실행에서

- `search_manual` 이 모은 청크가 0건이고
- 주문 조회(`check_order_status` 또는 문의의 관련 주문 선주입)가 한 번도 성공하지 않았으면

답을 고정 브리핑("근거를 찾지 못해 자동 답변을 보류했습니다…")으로 바꾸고 상담사 검토로 돌린다.
reason 앞에 `[근거 없음 — 자동 답변 차단]` 을 붙인다. 모델 초안은 버린다 — 근거 없이 쓴 일반 지식이라 상담사
화면에 남기면 그대로 전송될 위험만 있다.

막지 않는 것:

- **추가 질문(followUp)** — 되묻기는 지어내기가 아니다
- **모델이 이미 상담사에게 넘긴 답** — 그 답은 고객에게 나가지 않고 상담사 브리핑이 된다
- **근거는 있는데 그 근거가 틀린 경우** — 기간이 지난 행사 문서를 찾고도 "받을 수 있다" 고 답하는 경우(S06 유형)는
  유효기간 판단의 문제라 이 경계의 범위가 아니다. 섞으면 전후 차이의 원인이 갈리지 않는다

주문 조회 성공은 provenance 기록(`recordObservedOrder`, 인터셉터 몫)과 따로 `markOrderEvidence` 로 센다.
근거 유무가 인터셉터 구성에 따라 달라지면 안 되기 때문이다. 실패한 조회(남의 주문 → NOT_FOUND)는 근거가 아니다.

## 결과

실측 50건, 채점기 v2 (ADR 0010 "변경 2"):

- 근거 없을 때 거절·이관 0.69 → **1.0 (13/13)**, 범위 밖 10/10
- **대가: 검색이 실패한 정상 질문도 막힌다.** P03(적립금 유효기간)·P05(세금계산서)·P10(할부 조건)은 매뉴얼에 답이
  있지만 검색이 못 찾아 상담사로 넘어갔다. 이전에는 이 셋을 근거 없이 답했다(P10 은 카드사 정책을 지어냄).
  자동 답변이 40 → 25건으로 줄었다 — 검색 실패가 "지어낸 답" 대신 "상담사 업무량" 으로 바뀐 것이다.
  이 경계는 검색 품질 문제를 숨기지 않고 비용으로 드러낸다. 검색(청크 분할·별칭 사전)을 고치면 이 숫자가 돌아와야 한다
- 프롬프트 인젝션 질의 중 도구 없이 거절한 답(I01·I04)도 상담사로 간다 — 해롭지 않지만 업무량이다

## 대가

- 인사·잡담처럼 근거가 필요 없는 짧은 대화도 상담사로 간다. 데모 트래픽에서는 문제 삼지 않는다
- "근거가 있다" 를 청크 1건 이상으로만 판단한다. 엉뚱한 청크 하나만 걸려도 통과한다 — 근거의 *적합성*은 보지 않는다
