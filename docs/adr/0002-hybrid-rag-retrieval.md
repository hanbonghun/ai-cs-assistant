# 0002. 정책 검색은 vector 단독이 아니라 Hybrid 로 한다

- 상태: 채택
- 결정 시점: 2026-04~05 (2026-09-03 소급 기록)

## 맥락

초기 설계는 pgvector 코사인 유사도 단독 검색이었다. 87 케이스 골든셋에서 hard 케이스
(질문과 정책 문서의 표현이 크게 다른 경우) Recall@3 이 0.000 이었다.

**이 숫자가 나온 조건.** 골든셋 평가는 실제 임베딩 모델을 쓰지 않는다. 검색 로직을 바꿨을 때
원인을 분리하려면 임베딩이 결정론적이어야 해서 난이도별로 벡터를 고정했고, hard 는 코사인
유사도가 vector 임계값(0.75) 아래에 놓이도록 만들어 두었다. 즉 **0.000 은 측정 결과가 아니라
설계값**이다. 실제 `text-embedding-3-small` 로 잰 수치는 이 레포에 없다.

따라서 이 ADR 이 근거로 삼는 것은 "임베딩이 한국어 어휘 불일치에 약하다" 가 아니라
**"vector 단독으로 걸리지 않는 질의가 있을 때 키워드 경로가 그중 얼마를 건지는가"** 다.
뒤쪽은 실제 측정값이다 — hard 벡터를 게이트의 keyword 조건(`vector >= 0.5`)은 통과하도록
두었으므로, 회복 여부는 실제 한국어 질의와 청크 본문 사이의 `pg_trgm` word_similarity 가 가른다.

평가 코퍼스는 정책 문서 6종(각 1문장)이라 실제 색인(매뉴얼 10종을 청크로 분할)과 규모가 다르다.
`word_similarity` 는 최적 부분문자열로 정규화하므로 청크 길이에 민감하다 — 회복됐다는 사실은
남지만 0.143 이라는 값 자체는 운영에 그대로 이식되지 않는다.

## 결정

vector 검색과 `pg_trgm` 키워드 검색을 각각 수행하고 RRF(Reciprocal Rank Fusion)로 합친다.
한국어 질의는 `KoreanQueryPreprocessor` 로 어미·공통어를 제거하고,
vector floor gate 로 유사도가 바닥인 결과를 떨어뜨린다.

## 결과

- hard Recall@3 0.000 → 0.143, MRR 0.806 → 0.833. easy/medium Recall@1 은 1.0 유지
- negative 케이스(검색되면 안 되는 질의) NoMatchAccuracy 1.0 유지 — false positive 를 늘리지 않고 회복했다
- 검색 **로직**이 골든셋 회귀 테스트로 고정되므로 이후 변경의 효과를 숫자로 판정할 수 있다.
  임베딩 품질과 실제 문의 기준 품질은 이 테스트가 보장하지 않는다
- 대가: 검색 경로가 두 갈래가 되어 튜닝 표면이 늘었다(RRF 가중치, floor 임계, 전처리 규칙)
