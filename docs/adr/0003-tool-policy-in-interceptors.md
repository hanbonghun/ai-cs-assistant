# 0003. 툴 정책은 프롬프트가 아니라 인터셉터에서 코드로 강제한다

- 상태: 채택
- 결정 시점: 2026-05~09 (2026-09-03 소급 기록)

## 맥락

"툴을 6회 이상 호출하지 마라", "고액 주문은 자동 처리하지 마라" 같은 규칙을 프롬프트에 적어두면
모델이 대체로 따르지만 반드시 따르지는 않는다. 지키지 않았을 때 시스템이 알아채지 못하는 것이 문제다.

## 결정

툴 호출 전후에 끼어드는 `ToolCallInterceptor` 체인을 두고, 정책을 그 안에서 코드로 검사한다.
프롬프트에도 같은 규칙을 적지만 그것은 안내이고, 강제는 인터셉터가 한다.

- `ToolCallBudgetInterceptor` — 실행당 툴 호출 상한
- `HighValueOrderInterceptor` — 고액 주문에 정책 가드 노트 부착
- `OrderProvenanceInterceptor` — 실제로 조회에 성공한 주문 기록
- `RefundGuardrailInterceptor` — 환불 제안 4종 검사

차단은 예외가 아니라 `ToolResult.error(category, retryable, message)` 로 모델에 돌려준다.
모델이 에러 유형에 맞는 다음 행동(재시도 / 입력 수정 / 상담사 라우팅)을 고를 수 있어야 한다.

## 결과

- 규칙 위반이 조용히 통과하지 않는다. 위반은 툴 결과로 관측되고 `agentSteps` 에 남는다
- 정책을 프롬프트 문장이 아니라 테스트 가능한 단위로 만들 수 있다
- `beforeExecute` 가 차단하면 `afterExecute` 를 아예 돌리지 않는다 — 차단된 호출은 부수효과를 남기지 않는다
- 대가: 정책이 프롬프트와 코드 두 곳에 표현된다. 프롬프트 쪽이 낡으면 모델이 헛돌 수 있으므로 함께 갱신해야 한다
