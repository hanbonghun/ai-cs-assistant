# 0006. 에이전트가 실패해도 문의를 유실하지 않는다

- 상태: 채택
- 결정 시점: 2026-09-03

## 맥락

`MAX_STEPS`(8)를 다 쓰면 `IllegalStateException` 을 던져 분석이 실패했다.
8스텝까지 간 문의는 가장 복잡해서 사람이 봐야 하는 건인데, 답변도 상담사 브리핑도 남지 않고 사라졌다.
모델이 enum 에 없는 category/urgency 를 반환할 때도 하위 레이어의 `valueOf` 가 던져 분석 전체가 실패했다.

## 결정

실패를 예외로 끝내지 않고 항상 상담사에게 도달시킨다.

1. 스텝 소진 시 툴을 뺀 마지막 라운드를 한 번 더 돌려 요약을 받는다. 결과는 항상 `withHumanReview()` 로
   상담사 검토로 올린다 — 모델이 `false` 를 줘도 무시한다
2. 그마저 형식을 못 맞추면 코드로 브리핑을 합성한다(호출한 도구 목록·스텝 수, `reason` 에 `[자동 합성]` 표시)
3. enum 에 없는 값은 `GENERAL`/`MEDIUM` 으로 낮추고 warn 을 남긴다

## 결과

- 어느 경로로 가도 문의가 사라지지 않는다. 분류를 하나 틀리는 것이 문의를 잃는 것보다 낫다
- Langfuse outcome 이 `forced_final_answer` / `forced_final_synthetic` 으로 구분되어
  강제 종료가 얼마나 일어나는지 관측된다
- 대가: 실패가 조용해진다. warn 로그와 outcome 태그를 보지 않으면 모델이 형식을 못 맞추고 있다는 사실을
  놓칠 수 있다
