# 0005. 주문 조회는 소유자 스코프로만 하고, 타인 주문은 NOT_FOUND 로 응답한다

- 상태: 채택
- 결정 시점: 2026-09-03

## 맥락

`check_order_status` 가 주문번호만으로 조회했다. 고객이 타인의 주문번호를 문의에 적으면
상품명·결제금액·운송장번호가 그대로 노출됐다. 주문번호는 모델이 고객 문의 본문에서 읽어낸 값이다.

## 결정

소유자 스코프 조회를 **유일한** 진입점으로 만든다: `findById(orderId, customerIdentifier)`.
스코프 없는 오버로드는 남기지 않는다 — public 으로 남아 있으면 같은 구멍이 다시 난다.
신원은 `Inquiry.customerIdentifier` 에서 가져오며 모델이 준 인수를 신뢰하지 않는다.

소유자 불일치는 `PERMISSION` 이 아니라 **`NOT_FOUND`** 로 응답한다.

## 결과

- 둘을 구분해주면 주문번호를 하나씩 넣어보며 타인의 주문 존재 여부를 알아낼 수 있다.
  존재하지만 남의 것 / 아예 없음을 같은 응답으로 만들어 스캐닝을 막는다
- 승인 시점에도 같은 검사를 한 번 더 한다([0007](0007-writes-stage-only.md)) — 제안 시점과 실행 시점
  양쪽에서 소유자를 확인한다
- 한계: 이 검증은 `customerIdentifier` 만큼만 강하다. 현재 데모는 이 값을 클라이언트에서 받으므로
  실제 서비스에서는 인증된 세션에서 해결해야 한다. 코드에 `ponytail:` 주석으로 표시했다
